# Roadmap

Known gaps and planned improvements. File an issue if you'd like to pick one up.

## Reliability

- [ ] **Track local Helm chart content in Terraform.** Add a deterministic hash of the files under `fortiaigate/` to `helm_release.fortiaigate` values so template edits trigger a Helm upgrade instead of producing a no-op `terraform apply`.
- [ ] **Complete first-party workload health checks.** `api`, `webui`, `core`, scanners, and Triton now have readiness probes; add appropriate readiness/liveness or startup probes to `logd` and `license-manager`, and add liveness probes to other workloads where a safe endpoint exists.
- [ ] **Validate rendered ALB manifests in CI.** Render the chart with `ingress.className=alb`, validate it with a Kubernetes schema tool such as `kubeconform`, and assert the API, Core, and WebUI Service health-check paths. `helm lint` alone does not exercise or type-check these conditional resources sufficiently.
- [ ] **Make the WebUI entry point consistent.** The application serves `/ui` while `/` returns 404, but the README advertises `/`. Document `/ui` and, if practical, redirect the bare root path to it.

## Architecture

- [ ] **Revisit shared EFS persistence layout.** One RWX EFS PVC currently backs app data, PostgreSQL, and Redis. For production, consider Amazon RDS / ElastiCache, or at minimum separate PVCs per workload for better isolation and performance.

## Security defaults

- [ ] **Restrict EKS public endpoint.** `cluster_endpoint_public_access = true` is enabled without `cluster_endpoint_public_access_cidrs`. Default to private endpoint access or require a CIDR list at apply time.
- [ ] **Multi-AZ NAT.** `single_nat_gateway = true` is cheaper but introduces an AZ-level single point of failure.
- [ ] **Production TLS story.** Replace the self-signed cert generated by `tls.tf` with managed certificates appropriate to the ALB listener and in-cluster services.
- [ ] **Renew internal TLS proactively.** Until the self-signed certificate is replaced, configure renewal before its one-year expiration and rely on the existing checksum wiring to roll affected workloads.

## Lifecycle

- [ ] **Make EFS retention behavior explicit and safe.** `reclaim_policy = "Retain"` protects the Kubernetes PV, not the Terraform-managed `aws_efs_file_system`. Either protect or separate the filesystem so `terraform destroy` cannot remove retained data, or correct the teardown documentation to describe destructive behavior accurately.
- [ ] **Bump EKS default Kubernetes version.** `1.31` is in EKS extended support as of 2026-04-28 and reaches end of extended support on 2026-11-26. Move the default forward before then.

## Maintainability

- [ ] **Clarify health-check ownership in chart comments.** Kubernetes readiness probes control pod readiness; AWS ALB health paths come from the Service annotations. Update the API/WebUI comments to keep those mechanisms distinct.
- [ ] **Normalize WebUI Service YAML formatting.** Align its `metadata` indentation and template layout with the API and Core Services.

## Done

- ✅ Fix GPU/Triton scheduling: `gpu_enabled = false` cleanly removes Triton; Terraform-injected placement values flow through chart templates.
- ✅ Guard GPU licensed-node scheduling: when GPU is enabled and licenses are supplied, Terraform requires enough license entries to cover app node(s) plus the GPU node.
- ✅ Fix chart env rendering edge cases: manually supplied CSRF secrets render as `value`, and unset scanner RPC concurrency is omitted.
- ✅ Reliable TLS secret rotation: chart workloads honor the configured secret name; Terraform passes a deterministic cert checksum so first-party workloads, PostgreSQL, and Redis annotate pods to trigger rollouts on rotation.
- ✅ Chart standalone `helm lint` passes: added stub `license:` block and placeholder `image.repository`/`image.tag` defaults to `values.yaml` so the chart renders cleanly without Terraform supplying every value.
- ✅ API and WebUI readiness checks: added TLS-aware readiness probes and per-Service ALB health paths for API, Core, and WebUI so target groups probe endpoints that return 200.
